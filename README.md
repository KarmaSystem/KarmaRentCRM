# Rental Planner CRM

Mobile-first CRM для проката скутеров, мотоциклов, автомобилей и другого транспорта. Работает в браузере и как Telegram Mini App.

## Стабильное production-состояние

Текущая версия собрана и опубликована в GitHub/Railway. Изменения интерфейса не требуют новой миграции базы данных.

Проверка Railway:

```json
{"status":"ok","database":"ok","service":"rental-planner","migrations":{"applied":15,"latest":"0015_asset_conditions_service"}}
```

## Что реализовано

### Календарь и бронирования

- Общая календарная сетка с горизонтальной прокруткой дат и вертикальным списком объектов.
- Мобильная версия использует ту же структуру, что и ПК: фиксированная левая колонка объектов и календарь на всю ширину экрана.
- Объект в строке показывает название и номер.
- Booking bar показывает клиента, объект и номер.
- Поддерживаются короткие интервалы, половина ячейки, овальные брони и непрерывная подсветка текущего дня.
- Календарь расширяется до 366 дней по датам бронирований.
- Объекты можно менять местами drag-and-drop.
- Создание, изменение, продление, архивирование на 14 дней и восстановление бронирований.
- Даты, время, ставка, депозит и итоговая сумма пересчитываются автоматически.

### Финансы и аналитика

- Платежи, депозиты, расходы, ожидаемые суммы и чистая прибыль.
- Комиссия менеджера считается от полученной выручки.
- Для старых броней учитывается `paidAmount`, если отдельная платёжная запись ещё отсутствует.
- Аналитика по каждому объекту: выручка, расходы, прибыль, брони, арендные дни и простой за месяц.
- Поиск объекта и партнёра в аналитике.
- Период отчёта задаётся полями «От» и «До»; конечный день включается полностью.
- PDF-отчёт формируется в новом окне в виде карточек аренды.

### Партнёры, команда и роли

- OWNER, ADMIN, MANAGER и ACCOUNTANT.
- Партнёры с контактным именем, телефоном, email и каналом связи.
- Кнопки телефона, WhatsApp и Telegram.
- Поиск по объектам, партнёрам и команде.
- Менеджеры с телефоном, Telegram ID, email, паролем и процентом комиссии.
- Управление правами и журналом действий.

### Акты, фото и документы

- Акт передачи с партнёром и индивидуальными условиями объекта.
- Копирование и открытие ссылки на акт.
- Фото паспорта, фото объекта и PDF-документы добавляются через камеру или файлы.
- Медиа сохраняются в базе бронирования и доступны в карусели.

### Автопарк и сервис

- Добавление, редактирование, удаление и сортировка объектов.
- Пробег, сервис масла и вариатора, дата/пробег последнего обслуживания.
- Уведомления о сервисе и контрольных событиях.

### Уведомления и шапка

- Верхняя шапка содержит `?`, «Уведомления», переключатель темы и шестерёнку.
- Уведомления кликабельны и ведут в календарь, брони или автопарк.
- Настройки типов уведомлений открываются внутри колокольчика.
- Красный badge отображается только при наличии уведомлений.
- Подсказки закрываются крестиком и не должны перекрывать открытые модальные окна.
- Тема сохраняется в `localStorage`.
- Масштаб календаря (`Компактный`, `Обычный`, `Крупный`) и выход находятся в панели шестерёнки, а не в блоке «Мой бизнес». Ширина левой колонки, дневных ячеек и размер текста объекта реально меняются на мобильном; номер сохраняет читаемый размер, а название переносится по вертикали.

## Локальный запуск

```bash
cp .env.example .env
npm install
npx prisma generate
npx prisma migrate dev --name init
npm run dev
```

Для локального демо нужно явно выставить `DEMO_MODE=true`, поднять PostgreSQL и выполнить `npm run db:seed`. В production demo mode должен быть выключен.

## Переменные окружения

- `DATABASE_URL` — PostgreSQL connection string.
- `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` — данные BotFather.
- `TELEGRAM_WEBAPP_URL`, `APP_URL` — публичный Railway URL.
- `TELEGRAM_WEBHOOK_SECRET` — секрет webhook.
- `CRON_SECRET` — bearer secret для cron endpoint.
- `AUTH_SECRET` — секрет сессий.
- `OWNER_EMAIL`, `OWNER_PASSWORD`, `OWNER_TELEGRAM_ID` — данные владельца.
- `DEMO_MODE` — только локальный режим.

Секреты не хранятся в Git и не должны отправляться в чат.

## Railway

Railway Project должен содержать сервис приложения и PostgreSQL plugin. Dockerfile выполняет `prisma migrate deploy`, затем запускает standalone Next.js server.

Health endpoint:

```text
GET /api/health
```

Успешный ответ содержит `status: ok` и `database: ok`.

## Telegram

В BotFather задайте Web App URL на Railway-домене и установите `TELEGRAM_WEBAPP_URL`. Web App отправляет `Telegram.WebApp.initData` на `POST /api/telegram/auth`; backend проверяет HMAC-SHA256.

Для установки webhook один раз выполните:

```bash
curl -X POST https://YOUR-RAILWAY-DOMAIN/api/telegram/setup \
  -H "Authorization: Bearer YOUR_CRON_SECRET"
```

Webhook работает через `/api/telegram/webhook`. Команда `/start` создаёт профиль и отправляет кнопку открытия Mini App.

## Структура

- `app/page.tsx` — календарь, шапка, бронирования, аналитика и профиль.
- `app/page.module.css` — responsive layout, темы, календарь и мобильные стили.
- `app/api/analytics/route.ts` — финансовая агрегация, комиссии и operational alerts.
- `app/api/reports/route.ts` — отчёты по партнёрам и периодам.
- `app/api/health/route.ts` — проверка приложения и базы.

## Production workflow

1. Запустить `npm run typecheck`, `npm test` и `npm run build`.
2. Отправить проверенный commit в `main`.
3. Дождаться Railway redeploy и применения миграций.
4. Проверить `GET /api/health`.
5. Для клиента выполнить `Ctrl + F5`; в Telegram Mini App полностью закрыть и открыть окно заново.

## Зафиксированная мобильная версия — 03.10.2026

Мобильный профиль зафиксирован как рабочее состояние:

- блок «Мой автопарк» растягивается по количеству объектов и больше не ограничен внутренней высотой;
- все сохранённые байки отображаются в списке профиля, включая название, номер, категорию и статус;
- внутренний скролл автопарка убран, список прокручивается вместе со страницей;
- кнопка «Добавить» находится на одной строке с поиском;
- поиск занимает свободное место, кнопка добавления не перекрывает его;
- в строках автопарка кнопки «Редактировать» и «Удалить» вынесены под названием объекта и не накладываются друг на друга;
- названия и номера объектов не скрываются из-за кнопок действий;
- мобильные изменения ограничены профилем и не изменяют геометрию ПК-календаря.

### Текущее состояние ПК-календаря перед отдельной доработкой

- используется общая timeline-сетка с фиксированной левой колонкой объектов;
- ПК показывает календарь на 31 день и расширяет горизонтальную область прокрутки;
- для ПК доступны масштабы `Компактный`, `Обычный`, `Крупный`;
- booking bars имеют скруглённую овальную форму;
- текущий день выделяется непрерывной вертикальной полосой;
- названия объектов и номера выводятся в левой колонке;
- следующая отдельная задача — проверить и доработать только визуальную геометрию ПК-календаря, не меняя зафиксированную мобильную версию.

## Этап 03.10.2026 — фото, статусы объектов и ТО

- Просмотр фото бронирования открывается встроенным полноэкранным окном через React Portal в `document.body`; это исключает пустую страницу на мобильных WebView и обрезание модальной карточкой.
- В календаре название свободного объекта отображается ярко-зелёным, а объекта с активной арендой — красным; номер объекта сохраняется в подписи.
- На полосе бронирования показываются клиент, объект и ставка за сутки.
- В аналитике при нажатии на объект открывается карточка с выручкой, расходами, прибылью, простоем, текущим пробегом, контрольными значениями масла/вариатора, датой последнего ТО и примечанием.
- Из карточки объекта в аналитике доступна кнопка «Изменить ТО», ведущая к исходным данным объекта.
- Список бронирований и секция «Мой бизнес» используют устойчивые touch-scroll контейнеры для больших списков на iOS, Android и Telegram WebView.

## Этап 03.10.2026 — обратный отсчёт аренды

- Свободные названия объектов оставлены белыми.
- Названия объектов в активной аренде подсвечиваются ярко-зелёным.
- Цена убрана из полосы бронирования.
- Для аренды на 1–2 суток в полосе показывается только номер объекта и время возврата.
- Для более длинной аренды показываются клиент, объект и время возврата.
- За 24 часа до возврата цвет полосы плавно уходит в прозрачный розовый; за 2 часа становится красным.
- Исходный цвет, выбранный в карточке объекта, используется до начала обратного отсчёта.
- Цвет обновляется автоматически раз в минуту.

## Этап 03.10.2026 — профессиональный акт и удалённое принятие

- В акте теперь используется полный профессиональный набор условий аренды: запрет передачи третьим лицам, безопасность, топливо, пробег, ответственность за транспорт, угон/утрата, фотофиксация, аксессуары, досрочный возврат, продление и порядок удалённого принятия.
- Индивидуальные условия, заданные в карточке конкретного байка, по-прежнему имеют приоритет и попадают в акт.
- При создании акта CRM формирует длинную непредсказуемую ссылку и фиксирует статус `SENT`.
- Из карточки брони ссылку можно открыть, скопировать, передать через WhatsApp или Telegram. CRM не отправляет сообщения автоматически и не требует бота у гостя.
- Публичная страница акта работает без входа в CRM и показывает только данные конкретного токена.
- Гость вводит имя/ФИО и нажимает «Я ознакомлен и принимаю». Сервер фиксирует статус `ACCEPTED`, дату/время, имя, IP и User-Agent; повторное нажатие не создаёт новую запись.
- После принятия акт нельзя перезаписать повторным созданием: сохраняется именно принятая версия документа.
- Миграция `0017_act_guest_acceptance` добавляет статус, время отправки и сведения об удалённом принятии.

## Этап 03.10.2026 — финальная читаемость статусов объектов

- В фиксированной боковой колонке календаря свободные объекты остаются белыми, а объекты с активной арендой выделяются ярко-зелёным.
- Номер байка внутри короткой полосы брони также зелёный и остаётся читаемым независимо от цвета самой полосы.
- Из короткой подписи брони убран лишний символ `#`: отображается только номер объекта.


## Этап 03.10.2026 — категории автопарка и касса

- В карточке объекта доступны категории **Скутеры**, **Мощные байки**, **Электро**, **Мотоциклы**, **Автомобили**, **Недвижимость** и **Другое**.
- В «Мой автопарк» объекты визуально разделены по категориям; поиск продолжает работать по всему парку.
- В карточке брони операция по кассе выбирается явно: оплата аренды, принятие депозита или возврат депозита.
- «Полученные залоги» показывает только депозит, который остаётся на руках: принятые депозиты минус зафиксированные возвраты.
- «Ожидается оплата» относится только к реальному долгу аренды или отдельному неоплаченному продлению; создание акта автоматически фиксирует базовую аренду и депозит по правилам акта.
- В публичном акте есть крестик возврата назад в CRM/предыдущую страницу.


## Финансовая модель и подпись клиента — 03.10.2026

- **Выручка** — только платежи типа «Аренда»; депозит не является доходом.
- **Депозиты на руках** — полученные депозиты минус возвраты депозитов.
- **Касса** — выручка аренды плюс удерживаемые депозиты.
- **Чистый остаток** — выручка аренды минус расходы, комиссия партнёрам за лид и зарплата менеджеров. Филиальная комиссия не вычитается второй раз: она уже является комиссией партнёра.
- Комиссия партнёру — это комиссия за приведённый лид: она начисляется только если в брони выбран партнёр, а процент берётся с филиала байка (например, 15% для точки 1 и 10% для точки 2). Процент в карточке партнёра не используется. Оплата продления всегда исключается из комиссии.
- На публичной странице акта клиент обязан поставить согласие, указать имя/ФИО и поставить рукописную подпись пальцем или мышью. Подпись, согласие, дата, IP и User-Agent сохраняются в БД.

## Этап 03.10.2026 — филиалы, кассы и уведомления

- Добавлены филиалы/точки с собственной кассой и настраиваемой комиссией; для второй точки можно указать 10%.
- В карточке объекта доступны категория (скутер, мощный байк, электро, мотоцикл, автомобиль и др.), филиал/касса и цвет календарной полосы.
- Парк визуально разделён по категориям в профиле; платежи и расходы объекта учитываются в кассе его филиала.
- Депозит ведётся отдельно как общая касса: принятие депозита увеличивает деньги на руках, возврат депозита их уменьшает, но депозит не попадает в выручку.
- Аналитика показывает общую кассу, депозиты отдельно, комиссию партнёрам по точкам и зарплату всех активных менеджеров. Если два менеджера имеют по 12.5%, общая зарплата составляет 25% арендной выручки.
- Уведомление «Ожидается оплата» появляется только при непогашенном остатке аренды/продления; после принятия оплаты исчезает. Возвраты, выдачи и ТО показывают статус брони.
- В шестерёнке доступна расширенная «Справка CRM» с инструкцией по календарю, броням, актам, финансам, филиалам, кассам, ролям и уведомлениям.

## Финансовая модель — уточнение 04.10.2026

- Бронь с партнёром на байке точки 1 при аренде 600 000 ₫: партнёру начисляется 90 000 ₫ (15%). На точке 2: 60 000 ₫ (10%). Без партнёра: 0 ₫.
- Два менеджера по 12.5% получают суммарно 25% от фактически принятой арендной выручки. Третий менеджер добавляет свой процент.
- Продление не входит в партнёрскую комиссию. Депозит не входит ни в выручку, ни в комиссионную базу.
- Кнопка «+ Расход» в профиле позволяет выбрать «Общий расход компании» либо конкретный байк. Общий расход уменьшает общую прибыль; расход байка отображается в его доходности и уменьшает прибыль этого байка.
